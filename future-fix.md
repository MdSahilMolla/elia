## Genuinely unfixed — needs real feature work or infrastructure

No bounded patch exists for these; each needs a real design decision or capability this environment can't safely provide (see AGENTS.md's guidance on persistent hosting / secure credential storage). Investigated and commented on each issue; no code changed.

- **[#1273](https://github.com/MdSahilMolla/elia/issues/1273)** — recursive compounding unproven, no promoted generation. Not a code bug: `.evolution/ledger.jsonl` shows real attempts (4 rejected, 1 error, 0 promoted) and the last auto-improve cycle was blocked by provider rate limits before it could even attempt a generation. **Needs:** sustained paid model usage against a less rate-limited provider, not an engineering fix.
- **[#1278](https://github.com/MdSahilMolla/elia/issues/1278)** — hierarchical planning beyond 32-step/16-check/6-revision limits. The caps are deliberately-chosen anti-thrashing limits, each with a "seen live" incident in its own comment — bumping them risks reintroducing those incidents. `goalGraph.ts` already has `parentId`/`depth` nesting infrastructure (built for #1279's delegation), just not wired into the top-level flat `steps[]` plan. **Needs:** extending `proposal.ts`/`goalGraph.ts`/`replan.ts`/`loop.ts` to treat a step as a recursively-expandable sub-plan.
- **[#1281](https://github.com/MdSahilMolla/elia/issues/1281)** — remote approval + dashboard + cross-machine leases. A local dashboard already exists (`elia control status`, commit `2f5b6ef`) but isn't remote and has no budget/stale-lease columns. Lease ownership (`leaseOwnerAlive`) is unambiguously PID-based, breaking across machines/containers. **Needs:** a hosted always-on service or real coordination service beyond one machine's PID space.
- **[#1282](https://github.com/MdSahilMolla/elia/issues/1282)** — model-assisted stuck recovery (regex-only classifier). `stuck.ts` is confirmed still regex-only, unchanged since introduction. **Needs:** a new LLM call path inside an already-stuck repair loop — provider routing, prompt design, latency/cost budgeting, fallback to regex on model failure.
- **[#1283](https://github.com/MdSahilMolla/elia/issues/1283)** — typed project/service/git ops to replace shell choreography. The real blocker isn't verification (a plain `curl -sf` already works against the existing `shell-exit-zero` postcondition) — it's that there's no primitive for starting a background service, waiting for it to become ready, and guaranteeing teardown (`isLongRunningServerCommand` exists only to *refuse* running dev servers). Converges with #1286. **Needs:** a new managed-service primitive exposed as a tool, with its own governor assessment and contract, wired into the planner and role tool lists.
- **[#1284](https://github.com/MdSahilMolla/elia/issues/1284)** — persistent shared memory + auto-skill promotion. Board caps (`MAX_NOTES=200`) and the 15-exposure lesson-efficacy threshold are working as designed, not bugs. The one real gap: skill synthesis (`elia skills synth`) is still fully manual, with no autonomous trigger from the loop. **Needs:** new orchestration logic in `loop.ts` deciding *when* to trigger synthesis (concurrency/safety with an in-flight run, wiring `lessonTrials`'s "helps" verdict to a synthesis candidate score).
- **[#1286](https://github.com/MdSahilMolla/elia/issues/1286)** — multi-root workspaces + service lifecycle. `provisionTaskWorkspace` returns exactly one `allowedRoots` entry in every branch; no managed "service" concept exists anywhere. Converges with #1283 on the service-lifecycle half. **Needs:** a new per-root policy data model threaded through `isWithinTaskWorkspace`, tool sandboxing, and budget accounting, plus the same managed-service primitive #1283 needs.
- **[#1287](https://github.com/MdSahilMolla/elia/issues/1287)** — authenticated browser delegation with scoped preauth. `environment.ts` already draws a reasonable transport-vs-auth distinction in its readiness text (not a formal enum, but not silently claiming false readiness either). The real gap — actually storing and reusing a logged-in session's cookies/storage state — is secure credential/session storage this environment's own engineering guidance says to document rather than implement without the required infrastructure (secure keyring integration).
