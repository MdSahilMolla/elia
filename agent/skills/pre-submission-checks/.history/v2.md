# Pre-submission Checks

## Code Quality & Build

* When editing TypeScript in `src/tools`, separate function parameters and object properties with commas to prevent TS1005 errors.
* Before running `node --check` on `script.js`, execute `bun run build` in `workspace/portfolio-demo` so TypeScript artifacts and relative imports resolve correctly.
* For Python modules, install dependencies like `streamlit` and `pandas` using `pip3` before importing, and run `python3 -m py_compile` to catch syntax errors early.

## Submission Workflow

* Before invoking `submit_assumptions` or `submit_acceptance`, ensure every assumption or criterion has an associated verdict and that required deliverables are present.
* When invoking battmann, verify the `retrievedAt` field is a non-empty string no longer than 100 characters.

## UI & CSS Standards

* Prefix CSS class names with a project-specific prefix (e.g., `rp-`) to avoid leakage, keep specificity low, and avoid ID selectors.
* Use a black text on white background palette with `system-ui` font; keep text lowercase by default with `text-transform: lowercase` on headings and paragraphs.
* Use CSS Grid for taxonomy and concept card sections, giving each cell a 1px solid black border.
* Add a marquee-style footer using CSS animation on a container div with inline text.

## File & Tooling Safety

* Before targeting nested paths, verify existence using `grep` on the parent directory.
* Do not assume `App.svelte` exists in `src/` during reviews; confirm the project uses vanilla JS or other frameworks.
* When adding skills with `npx skills add`, include the `-y` flag and provide an `--agent` value to satisfy required options.
