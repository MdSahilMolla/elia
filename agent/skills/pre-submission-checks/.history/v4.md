# Pre-Submission Checks

## Build & Environment

Always run bun commands (`install`, `build`, `dev`, `test`) from the `workspace/flower-blooming` directory, not from the repository root, because `package.json` and source files are located there. Before executing git commands, verify the current working directory exists to avoid exit code failures.

## File System Safety

When invoking file-system commands such as `list_files`, ensure the target path is a valid existing directory under `workspace/flower-blooming`; a non-existent path will cause the command to fail. Ensure all file and command paths are relative to the workspace root instead of including absolute user paths that cause duplication.

## Submission & Verification

Before invoking `submit_assumptions` or `submit_acceptance`, ensure every item has an associated verdict and all required deliverables are present. Verify that battmann `retrievedAt` fields are non-empty strings under 100 characters.

*   Ensure `submit_acceptance` includes a verdict for every acceptance criterion before invocation to avoid submission failure.
*   When calling `risk_assessment`, include a non-empty `sourceDate` string of at most 100 characters in the first factor.
*   When invoking `create_question`, set the `horizon` field to a valid ISO date or timestamp.

## UI & CSS Standards

*   **index.html:** Must be <= 150 lines and include a meta description (target ~90 lines).
*   **styles.css:** Must be <= 80 lines with a trailing newline (target ~22 lines).
*   **Naming:** All CSS class selectors must be prefixed with `.` and all class names must begin with `rp-` to avoid leakage.
*   **Style:** Use a black-on-white palette with `system-ui` font and lowercase text by default. Use CSS Grid for taxonomy sections (cells 1px solid black border, `taxonomy` ID) and concept cards. Implement a fixed top navigation (`position:fixed; top:0;`) with a backdrop-filter. Style buttons as pill-shaped with hover effects. Ensure these styles are preserved.
*   **Dependencies:** Do not add external dependencies; the site must be pure HTML/CSS only.
*   **Minimalism:** Apply ponytail minimalism: keep CSS concise, avoid redundant rules, and use subtle interactive states such as hover lift and shadow for phases and buttons.
*   **Mobile:** Add a responsive breakpoint at 768px to adjust fonts and navigation for mobile.

## Tooling Safety

When checking for empty lines in CSS files using `grep`, expect exit code 1 if no matches are found, so use `awk` or handle non-zero exit codes gracefully.

If `preview` returns HTTP 500, delete stale artifacts with `rm -rf .next` before retrying.
