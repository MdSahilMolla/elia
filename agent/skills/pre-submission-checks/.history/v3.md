# Pre-Submission Checks

## Build & Quality Control

Before finalizing any change, run `bun run typecheck` for type validation. If no typecheck script exists, run `bun run build` instead or add the script to package.json. Always run bun commands (install, build, test) from the directory containing package.json (typically `workspace/flower-blooming`), not from top-level folders.

For TypeScript in `src/tools`, separate function parameters and object properties with commas to avoid TS1005 errors. For Python modules, install dependencies with `pip3` (e.g., `streamlit`, `pandas`) and run `python3 -m py_compile` to catch syntax errors early.

To preview a site, run `bun run dev` followed by `preview http://localhost:3000`. If preview returns HTTP 500, delete stale artifacts with `rm -rf .next` before retrying.

## Submission & Verification

Before invoking `submit_assumptions` or `submit_acceptance`, ensure every item has an associated verdict and all required deliverables are present. Verify that battmann `retrievedAt` fields are non-empty strings under 100 characters.

## UI & CSS Standards

Use a project-specific prefix for class names (e.g., `rp-`) to avoid leakage and keep specificity low. Stick to a black-on-white palette with `system-ui` font and lowercase text by default.

For layout, use CSS Grid for taxonomy sections (give cells 1px solid black border and an `taxonomy` ID) and concept cards. Implement a fixed top navigation using `position:fixed; top:0;` with a backdrop-filter. Style parenthetical buttons using a wrapper `span` or `button::before` with a hover effect that fills the background while keeping text transparent until hovered. Add a responsive breakpoint at 768px to adjust fonts and navigation for mobile.

When drafting research paper themes, start with static `index.html` and `styles.css` without build tools, and include footer citations referencing the source.

## File & Tooling Safety

Before targeting nested paths, verify parent directory existence using `grep`. Do not assume `App.svelte` exists without confirming the framework. When adding skills via `npx skills add`, include `-y` and `--agent` flags.
