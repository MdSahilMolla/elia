# Submission and Command Pre-Checks

## Submissions
Before calling `submit_acceptance` or `submit_assumptions`, verify that every
acceptance criterion or assumption has an associated verdict. Missing
verdicts will cause the submission to fail.

When invoking `create_question`, set the `horizon` field to a valid ISO date
or timestamp.

## File System Commands and Paths
When executing file-system commands such as `list_files`, confirm that the
target path is a valid existing directory. Keep all paths relative to the
workspace root; avoid including absolute user paths that cause duplication.

When invoking nested paths (e.g., `src/autonomy/loop.ts`), verify the file
exists. Use `grep` on the parent directory to list available files, and
handle non-zero exit codes from `grep` gracefully (e.g., exit code 1 if no
matches are found).

Verify that files like `SKILL.md` exist under `agent/skills/` relative to the
workspace root before attempting to read them.

## Execution Context and Commands
Always execute `bun` commands (install, build, dev, test) from the
`workspace/flower-blooming` directory, not from the repository root, because
`package.json` and source files reside there.

When invoking `npx skills add`, include the `-y` flag to auto-approve and
provide `--agent '*'` to satisfy required options and avoid exit code 1.

Avoid executing commands that require interactive input (e.g., Python's
`input()`) via `run_command`; use only non-interactive commands in this
environment.

## Build and Output Validation
When checking TypeScript outputs with `node --check`, first run `bun run build`
in the appropriate workspace (`workspace/portfolio-demo`) to ensure all
compilation artifacts are present and relative imports resolve.

Ensure `index.html` is no more than 150 lines and includes a meta description.
Ensure `styles.css` is no more than 80 lines, uses class selectors prefixed with
`.`, and all class names begin with `rp-`. Apply the ponytail minimalism style:
keep CSS concise, avoid redundant rules, and use subtle interactive states such
as hover lift and shadow for phases and buttons. Use a black/white palette,
system‑UI font, fixed top navigation, marquee footer, and pill‑shaped buttons;
preserve these styles.

## Risk Assessment
When calling `risk_assessment`, include a non-empty `sourceDate` string in
the first factor. This string must be at most 100 characters long.
