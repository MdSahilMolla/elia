# Elia Project Development Workflow

## Verification & Build
Run `bun run typecheck` before making any changes. If a typecheck script is missing, run `bun run build` or add one, and always execute `node --check` after building to confirm all TypeScript outputs compile.

## Site Preview
To view the site, run `bun run dev` then preview `http://localhost:3000`. If you receive an HTTP 500 error, delete stale Next.js artifacts with `rm -rf .next` before retrying.

## Working Directory
Execute all bun commands, file references, and file-system operations from the `workspace/flower-blooming` root using relative paths only. Never run from the repository root or use absolute user paths. Verify that target files exist before reading them.

## Command Handling
When running commands that may exit with non-zero codes (e.g., `grep`, `list_files`, `npx skills add`, `git worktree add`, `risk_assessment`, `create_question`), handle the exit status gracefully. Supply required flags or arguments (`-y`, `--agent '*'`, non-empty `sourceDate` ≤100 chars, valid ISO date for `horizon`).

## Website Design
Use a static `index.html` and a single `styles.css` only, with no build tools or external dependencies. Keep `index.html` ≤150 lines and include a meta description. Keep `styles.css` ≤80 lines with class selectors prefixed by `.` and names beginning with `rp-`. Keep CSS concise, avoid redundant rules, and use subtle interactive states such as hover lift and shadow for phases and buttons.
