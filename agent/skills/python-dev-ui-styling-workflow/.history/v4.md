# Python Development and UI Styling Workflow

## Environment & Workflow
- Run all Bun commands (`install`, `build`, `dev`, `test`) from the `workspace/flower-blooming` directory. Reference files using relative paths only; avoid running from the repository root or using absolute user paths to prevent duplication.
- Keep all command paths relative to the workspace root. Do not include absolute user paths.
- When invoking nested paths (e.g., `src/autonomy/loop.ts`), verify the file exists first. Use `grep` on the parent directory to list available files if unsure.
- When invoking `grep` or commands like `list_files`, handle non-zero exit codes gracefully (e.g., exit code 1 when no matches are found).
- Before checking TypeScript outputs with `node --check`, run `bun run build` in the appropriate workspace (`workspace/portfolio-demo`) so compilation artifacts and relative imports resolve.
- When invoking `npx skills add`, include the `-y` flag to auto‑approve and provide `--agent '*'` to satisfy required options.
- Run `bun run typecheck` before finalizing any change; if the project lacks a typecheck script, use `bun run build` to validate TypeScript types or add a typecheck script to `package.json`.
- Ensure file‑system commands like `list_files` target paths that are valid existing directories under `workspace/flower-blooming`; a non‑existent path will cause the command to fail.
- Before calling `submit_acceptance` or `submit_assumptions`, ensure that every acceptance criterion or assumption has an associated verdict; otherwise the submission will fail.
- Run `bun run dev` and then `preview http://localhost:3000` to view the site. If `preview` returns HTTP 500, delete stale Next.js artifacts with `rm -rf .next` before retrying.
- Verify that files like `SKILL.md` exist under `agent/skills/` relative to the workspace root before attempting to read them.
- Before running `git worktree add`, list existing worktrees for the target branch with `git worktree list` and skip the add if one already exists to avoid exit code 128.

## Python Safety
- Install packages with `pip3` before importing them.
- Pre‑compile modules using `python3 -m py_compile` prior to execution to detect syntax errors and avoid runtime hangs.
- Avoid executing commands that require interactive input (e.g., Python’s `input()`) via `run_command`; use only non‑interactive commands in this environment.
- Avoid using `echo -e` for piped input to Python scripts. Use `printf` instead.

## UI & Theme Design
- Start a research‑paper theme website with a static `index.html` and a single `styles.css`. No build tools or external dependencies are required.
- **File Constraints:** Ensure `index.html` is no more than 150 lines and includes a meta description. Ensure `styles.css` is no more than 80 lines, uses class selectors prefixed with `.`, and all class names begin with `rp-`.
- **Colors & Fonts:** Use a black/white palette with system‑UI fonts.
- **Layout:** Implement fixed top navigation using `position: fixed; top: 0;` with a subtle backdrop-filter. Include a marquee footer.
- **Components:** Use pill‑shaped buttons.
- **Style Quality:** Apply minimalism. Keep CSS concise, avoid redundant rules, and use subtle interactive states such as hover lift and shadow for phases and buttons.

## Tool Usage Patterns
- When calling `risk_assessment`, include a non‑empty `sourceDate` string of at most 100 characters in the first factor.
- When invoking `create_question`, set the `horizon` field to a valid ISO date or timestamp.
