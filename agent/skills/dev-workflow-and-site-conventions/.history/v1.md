# Development Workflow and Site Conventions

## Execution Context and Types

Always run `bun` commands (install, build, dev, test) from `workspace/flower-blooming`, where the package.json and sources live. Before finalizing any change, run `bun run typecheck`; if absent, use `bun run build` for validation. When checking specific scripts like `node --check` on `script.js`, ensure compilation artifacts exist by building in the specific directory first (e.g., `workspace/portfolio-demo`) so relative imports resolve. Verify file existence before targeting nested paths; use `grep` on parent directories to list available files.

## Preview and Cleanup

To view a site, run `bun run dev` followed by `preview http://localhost:3000`. Note that `preview` auto-reloads and exits normally, while `bun run dev` runs persistently. If preview returns HTTP 500, delete stale Next.js artifacts with `rm -rf .next` before retrying.

## Research Paper Theme Constraints

When building a research paper theme website, start with a static `index.html` and `styles.css` without build tools or dependencies. The site must remain pure HTML/CSS. Adhere to these strict styling rules:
- Use only class selectors prefixed with `rp-`, beginning with `rp-`.
- Keep `styles.css` concise and under 80 lines; aim for minimalism.
- Apply subtle interactive states like hover lift and shadow for phases and buttons.
- Ensure `grep` commands for CSS checks handle non-zero exit codes gracefully.

## Utility Commands

When adding a skill with `npx skills add`, include the `-y` flag to auto-approve and `--agent '*'` to satisfy required options and avoid exit code 1.
