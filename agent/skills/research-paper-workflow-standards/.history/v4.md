# Research Paper Workflow Standards

## Development & Tooling
- Execute all Bun commands (`install`, `build`, `dev`, `test`) and reference files strictly from the `workspace/flower-blooming` root. Use relative paths only; never run from the repository root or use absolute user paths to prevent duplication.
- Before finalizing any change, run `bun run typecheck`. If that script is missing, use `bun run build` to validate TypeScript types.
- If using `node --check` on outputs, ensure you ran `bun run build` in the workspace first so compilation artifacts exist.
- To view the site, run `bun run dev` and then `preview http://localhost:3000`. If `preview` returns HTTP 500, delete stale Next.js artifacts with `rm -rf .next` before retrying.
- Before running `git worktree add`, list existing worktrees for the target branch with `git worktree list` and skip the add if one already exists to avoid exit code 128.

## Research Paper Theme Implementation
- Start research-paper sites with a static `index.html` and `styles.css`. Do not require build tools or external dependencies for the base theme.
- **Design Standards:** Use a black/white palette, system-ui font, fixed top navigation, marquee footer, and pill-shaped buttons. Preserve these styles.
- **Navigation:** Implement a fixed top navigation bar using `position:fixed; top:0;` and a subtle backdrop-filter to match the humanastudio.com aesthetic.
- **CSS Rules:** Use class selectors prefixed with `.`; all class names must begin with `rp-`. Keep CSS concise (ponytail minimalism) and avoid redundant rules.
- **File Limits:**
  - `index.html`: Must be ≤ 150 lines and include a meta description.
  - `styles.css`: Must be ≤ 80 lines with a trailing newline.

## CLI & Command Safety
- When invoking `npx skills add`, include `-y` for auto-approval and `--agent '*'` to satisfy required options.
- Handle non-zero exit codes from commands like `grep` gracefully (e.g., exit code 1 when no matches are found).
- Verify that files like SKILL.md exist under `agent/skills/` relative to the workspace root before attempting to read them.
- Avoid executing commands requiring interactive input (e.g., Python's `input()`) via `run_command`; use only non-interactive commands.
- When using `run` for piped input to Python scripts, use `printf` instead of `echo -e`.

## Python Dependency Management
- When using pip for Python dependencies (e.g., streamlit, pandas), install them with `pip3` before attempting to import them in the project.
- Pre-compile Python modules with `python3 -m py_compile` before executing imports to catch syntax errors and avoid runtime hangs caused by backend import timeouts.

## Submission & Safety
- Before calling `submit_acceptance` or `submit_assumptions`, ensure that every acceptance criterion or assumption has an associated verdict; otherwise the submission will fail.
- When calling `risk_assessment`, include a non-empty `sourceDate` string of at most 100 characters in the first factor.
- When invoking `create_question`, set the `horizon` field to a valid ISO date or timestamp.
