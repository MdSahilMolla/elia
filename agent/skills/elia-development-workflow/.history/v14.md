# Elia Development Workflow

## Workspace and Commands
Run bun commands (install, build, dev, test) from the repository root unless a project has explicit subproject documentation. Use `cwd` explicitly in commands that operate on subdirectories. When invoking file-system commands such as `list_files`, ensure the target path is a valid existing directory. Use file and command paths relative to the workspace root; avoid absolute user paths that cause duplication. Before executing git commands, verify the current working directory exists to avoid exit code 1 failures.

## Type Checking
Before finalizing any change, run `bun run typecheck`. If the project lacks a typecheck script, use `bun run build` for type validation or add the script to `package.json`.

## Submission
Ensure `submit_acceptance` includes a verdict for every acceptance criterion before invocation. For `submit_assumptions`, ensure each assumption has an associated verdict before calling. Before invoking `submit_acceptance`, verify that all required game deliverables are present.

## File Safety and Verification
Before targeting nested paths (e.g., `src/autonomy/loop.ts`), verify the file exists and use `grep` on the parent directory to list available files. When checking for empty lines in CSS files using `grep`, expect exit code 1 if no matches are found, so use `awk` or handle non-zero exit codes gracefully. Ensure all referenced paths are relative to the workspace root.

## Command Line Tools
When invoking `battmann`, provide a non-empty `retrievedAt` string no longer than 100 characters to satisfy input validation.

## Skill Management
When adding a skill with `npx skills add`, include the `-y` flag to auto-approve and provide `--agent '*'` to satisfy required options and avoid exit code 1.
