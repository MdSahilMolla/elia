# Elia Development Workflow

## Workspace and Commands
Run bun commands (install, build, dev, test) from the repository root unless a project has explicit subproject documentation. Use `cwd` explicitly in commands that operate on subdirectories.
When invoking file-system commands such as `list_files`, ensure the target path is a valid existing directory.

## Type Checking and Building
Before finalizing any change, run `bun run typecheck`. If the project lacks a typecheck script, use `bun run build` for type validation or add the script to `package.json`.
Ensure all function parameters and object properties in TypeScript files under `src/tools` are separated by commas to avoid TS1005 errors.

## Frontend and Static Sites
For static sites, keep `index.html` to 150 lines or fewer and include a meta description. Keep `styles.css` to 80 lines or fewer with a trailing newline.
All CSS selectors must be prefixed with `rp-` and start with a dot (e.g., `.rp-class`). Use a black text on white background palette, system-ui font, fixed top navigation, marquee footer, and pill-shaped buttons. Apply ponytail minimalism by keeping CSS concise, avoiding redundant rules, and using subtle interactive states such as hover lift and shadow. Do not add external dependencies; the site must be pure HTML/CSS only.

## Previewing the Application
Run `bun run dev` then use `preview http://localhost:3000` to view the site. The preview command auto-reloads and exits normally, whereas `bun run dev` never exits. If preview returns HTTP 500, delete stale Next.js artifacts with `rm -rf .next` before retrying.

## UI Implementation Patterns
- Use CSS Grid for taxonomy and concept card sections; give each grid cell a 1px solid black border for a clean, minimalist look.
- Style parenthetical buttons with a `button::before` or a wrapping `span` that contains parentheses, and apply a hover effect that fills the background while keeping the text transparent until hovered.

## File Safety and Verification
Before targeting nested paths (e.g., `src/autonomy/loop.ts`), verify the file exists and use `grep` on the parent directory to list available files.
When checking for empty lines in CSS files using `grep`, expect exit code 1 if no matches are found, so use `awk` or handle non-zero exit codes gracefully.

## Submission
Ensure `submit_acceptance` includes a verdict for every acceptance criterion before invocation. For `submit_assumptions`, ensure each assumption has an associated verdict before calling.
Before invoking `submit_acceptance`, verify that all required game deliverables are present and each acceptance criterion has an associated verdict.

## Python Development
Install Python dependencies like streamlit and pandas using pip3 before attempting to import them in the project.
Precompile Python modules with `python3 -m py_compile` before executing imports to catch syntax errors and avoid runtime hangs.

## Command Line Tools
When invoking `battmann`, provide a non-empty `retrievedAt` string no longer than 100 characters to satisfy input validation.

## Skill Management
When adding a skill with `npx skills add`, include the `-y` flag to auto-approve and provide `--agent '*'` to satisfy required options and avoid exit code 1.
