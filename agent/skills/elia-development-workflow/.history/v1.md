# Elia Development Workflow

## Type Checking and Building
Before finalizing any change, run `bun run typecheck`. If the project lacks a typecheck script, use `bun run build` for type validation or add the script to package.json.

## Context-Specific Commands
- The elia project's package.json resides in `workspace/flower-blooming`. Always run bun commands (install, build, test) from this directory, not from the top-level flower-blooming folder.
- Before running `node --check` on script.js, run `bun run build` in `workspace/portfolio-demo` and run `node --check` from that directory to ensure all TypeScript compilation artifacts are present and relative imports resolve.

## Previewing the Application
Run `bun run dev` then use `preview http://localhost:3000` to view the site. The preview command auto-reloads and exits normally, whereas `bun run dev` never exits. If preview returns HTTP 500, delete stale Next.js artifacts with `rm -rf .next` before retrying.

## UI Implementation Patterns
- For a marquee-style footer that repeats navigation phrases, use CSS animation on a `<div class="marquee">` containing inline text.
- Use CSS Grid for taxonomy and concept card sections; give each grid cell a 1px solid black border for a clean, minimalist look.
- Use a black text on white background palette with system-ui font, and keep all text lower-case by default using CSS `text-transform: lowercase` for headings and paragraphs.

## File and Migration Safety
- Do not assume Svelte source files like `App.svelte` exist in `src/` during migration reviews, as the project may have already converted to vanilla JavaScript.
- Before targeting nested paths (e.g., `src/autonomy/loop.ts`), verify the file exists and use `grep` on the parent directory to list available files.

## Skill Management
When adding a skill with `npx skills add`, include the `-y` flag to auto-approve and provide `--agent '*'` to satisfy required options and avoid exit code 1.

## Research Paper Theme Websites
When creating a research paper theme website, start with a static `index.html` and a single `styles.css`; no build tools or dependencies are required.
