# Elia Development Workflow

## Workspace and Commands

Always run `bun` commands (install, build, dev, test) from the `workspace/flower-blooming` directory, not from the repository root, because the package.json and source files are located there. Use `cwd` explicitly in commands that operate on subdirectories. Use file and command paths relative to the workspace root. Before executing git commands, verify the current working directory exists.

## Type Checking and Testing

Before finalizing any change, run `bun run typecheck`. If no typecheck script is available, use `bun run build` for type validation or add the script to package.json. In TypeScript files under `src/tools`, separate function parameters and object properties with commas to avoid TS1005 errors. Run the following commands with the specified environment variables to validate your changes:

```
NO_COLOR=1 ANTHROPIC_API_KEY=test-key-for-local-tests bun run typecheck
NO_COLOR=1 ANTHROPIC_API_KEY=test-key-for-local-tests bun test
```

## Development and Preview

To view the site, run `bun run dev` then `preview http://localhost:3000`. The `preview` tool auto-reloads and exits normally, whereas `bun run dev` never exits. If preview returns HTTP 500, delete stale Next.js artifacts with `rm -rf .next` before retrying.

## File and Path Safety

Before targeting nested paths, verify the file exists (e.g., `src/autonomy/loop.ts`) and use `grep` on the parent directory to list available files. When invoking file-system commands such as `list_files`, ensure the target path is a valid existing directory under `workspace/flower-blooming`; a non-existent path will cause the command to fail. When checking for empty lines in CSS files using `grep`, expect exit code 1 if no matches are found, so handle non-zero exit codes gracefully.

## Submission Protocol

Before invoking `submit_acceptance`, ensure every acceptance criterion has an associated verdict. Before invoking `submit_assumptions`, ensure each assumption has an associated verdict. Ensure that all required deliverables are present before invoking submission.

## Project Conventions

Install Python dependencies using `pip3` before attempting to import them. When invoking `npx skills add`, include the `-y` flag to auto-approve and provide `--agent '*'` to satisfy required options. When creating a research paper theme website, start with a static `index.html` and a single `styles.css`; no build tools or dependencies are required. Ensure `index.html` is <= 150 lines and includes a meta description. Ensure `styles.css` is <= 80 lines, uses class selectors prefixed with `.` and all class names begin with `rp-`. All CSS should use a black/white palette, system-ui font, fixed top navigation (`position:fixed; top:0;` with subtle backdrop-filter), marquee footer, and pill-shaped buttons. Do not assume Svelte source files like `App.svelte` exist in `src/` during migration reviews. Inspect `git diff` and run `git diff --check` before reporting completion.
