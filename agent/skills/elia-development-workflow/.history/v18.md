# Elia Development Workflow

## Workspace and Commands

Run bun commands (install, build, dev, test) from the repository root unless a project has explicit subproject documentation. Use `cwd` explicitly in commands that operate on subdirectories. Use file and command paths relative to the workspace root. Before executing git commands, verify the current working directory exists.

## Tool Usage

When calling `risk_assessment`, include a non-empty `sourceDate` string of at most 100 characters in the first factor. When invoking `create_question`, set the `horizon` field to a valid ISO date or timestamp.

## Type Checking and Testing

Before finalizing any change, run type checking and tests with:
```
NO_COLOR=1 ANTHROPIC_API_KEY=test-key-for-local-tests bun run typecheck
NO_COLOR=1 ANTHROPIC_API_KEY=test-key-for-local-tests bun test
```

## Submission

Ensure `submit_acceptance` includes a verdict for every acceptance criterion before invocation. For `submit_assumptions`, ensure each assumption has an associated verdict before calling. Before invoking `submit_acceptance`, verify that all required deliverables are present.

## Git Verification

Inspect `git diff` and run `git diff --check` before reporting completion.
